# 独立方法推演与现实综合

## 目的

避免先形成一个人物结论，再让格局、调候、盲派等方法分别为同一答案背书。每种方法必须只读取冻结的排盘事实，在不知道其他方法结论的条件下完成自己的命理推演和现实候选。全部方法输出完成后，综合层才能归并现实方向、识别关系并确定置信度。

## 方法家族

### 主要家族

下列方法应先独立生成并校验；`complete` 时各自至少形成两条技术结论和两条现实候选。三轮局部修复后仍失败时按 [method-failure-and-recovery.md](method-failure-and-recovery.md) 归类，不得用其他方法补齐：

1. `pattern_structure`：格局成败、月令任务、顺逆配合、相神救应、清纯混杂、价值形成链和岁运中的成败变化。
2. `momentum_configuration`：气势、意向、形象方局、集中与分散、顺势与转化、完整成象和中断条件。
3. `climate_adjustment`：寒暖燥湿、结构舒展条件、行动节奏、环境适配、恢复成本和岁运中的缓解或过度。
4. `ten_god_dynamics`：十神网络中的动机、行动顺序、资源交换、权责、评价、收入与关系反馈链。
5. `root_seed_flower_fruit`：来源、培养、外显、沉淀、传承和同一时期根苗花果的共同作用。
6. `blind_school`：宾主、体用、做功、主体、工具、对象、结果归属、成本、虚实完整性和现实取象。
7. `timing_continuity`：大运主题、流年执行、前后承接、阶段变化、现实惯性和下一年伏笔。

### 部分独立家族

下列方法在 `complete` 时各自至少形成一条技术结论和一条现实候选，但与主要家族共享较多底层事实，不能被当作完全独立的一票：

1. `position_relationship`：宫位、六亲、主体位置、资源接口、人生位置和早晚阶段。
2. `stem_branch_dynamics`：月令、旺衰、根透、制化、流通、阻塞、刑冲合害破和合化条件。

扶抑、病药、通关、十二长生、空亡、墓库、透干、通根、合化和刑冲合害破是方法内部机制，不得分别冒充独立方法家族重复计票。

## 方法隔离

每个 `method_analysis` 只能读取 `prepare_method_input.py` 生成的主题隔离输入，并登记其 `method_input_sha256`。其中允许使用：

- `chart_facts`；
- `chart_audit`；
- `five_elements`；
- 与本方法直接有关的确定性大运流年数据；
- `person` 与 `request` 中只用于限制现实范围的年龄、年代、城市等基础事实。

它不得读取原始 `core-input.json`、报告预检中的关注方向、`reality_context`、`social_context_model`、其他方法的技术结论、现实候选、综合判断、报告判断或用户校准答案。`source_method_ids_read` 必须为空数组。现实经历只能在全部方法完成后用于现实确认，不得进入独立命理推演。

## 每种方法的两层输出

正式方法包只能使用 `schemas/method-packet.schema.json`。先由根目录 `scripts/initialize_method_packets.py` 为九个方法生成彼此分离的草稿；每种方法只读取主题隔离输入、自己的草稿、本Schema和本方法所需参考资料。完成后删除 `_draft_notice`，替换全部 `__AI_FILL__`，另存正式方法包并立即校验。不存在其他方法包Schema，不得根据文件名习惯自行猜测。

### 技术结论

每条 `technical_conclusion` 必须包含：

- 稳定编号；
- 具体命理观察；
- 至少两步机制链；
- 排盘事实引用和实体证据引用；
- 成立条件与反向条件；
- 时间范围和置信度。

不能只写“格局支持事业”“调候影响健康”等方法名称。

### 现实候选

每条 `reality_hypothesis` 必须从本方法自己的技术结论导出，并包含：

- 稳定编号和来源技术结论；
- 固定现实领域与标准化现实方向；
- 完整现实判断；
- 两条可观察表现；
- 成立条件、反证和禁止外推；
- 相比本方法其他候选新增的信息；
- 时间范围和现实确认状态。

独立方法不得读取其他方法候选后故意改写成同一方向。不同方法自然得到相同现实方向时，由综合层识别，而不是由方法层预先协调。

## 八领域检查

每个 `complete` 方法都必须对 `self_growth`、`love_partner`、`career`、`finance_resources`、`body_emotion`、`family_growth`、`learning`、`mobility` 各登记一条 `domain_assessment`：

- `supported`：本方法形成了该领域现实候选，必须列出本领域全部 `hypothesis_ids`；
- `insufficient_evidence`：本方法实际检查过，但不足以形成现实候选；
- `not_applicable`：该领域超出本方法在本盘中的合理推演范围。

十神动力、宫位六亲、干支动力、盲派和岁运连续性是 `love_partner` 锚点方法，必须在 `supported` 与 `insufficient_evidence` 中二选一，不得用 `not_applicable` 跳过。领域检查用于证明“分析过”，不是要求每种方法硬写八条候选。

## 现实综合

综合层只读取全部被冻结的 `reality_hypotheses`，按现实语义归并，不重新推命。必须区分：

- `same_direction`：不同方法在同一现实领域指向实质相同的表现或机制；成员原始 `normalized_direction` 可以措辞不同，由综合层统一命名并说明语义重合依据；
- `complementary`：分别增加同一人物的不同侧面；
- `conditional`：不同条件下表现不同；
- `stage_specific`：长期结构与阶段变化不同；
- `hierarchical`：总判断与具体表现；
- `conflict`：相同时间、对象、条件和口径下不能同时成立。

综合层必须记录每个现实簇中的候选、方法、独立家族、反证、现实确认状态和报告角色。不得把共享同一底层结构的多个术语机械计算为多票，也不得因为独立生成的两个候选没有使用完全相同的字符串就否认真实的语义同向。

## 置信度与报告角色

- `primary`：至少两个主要方法家族独立同向，无未解决的事实冲突；可以进入报告主要判断。
- `supplemental`：只有一个主要方法支持，但新增实质信息、成立条件明确、可观察、没有事实冲突；可以作为补充侧面，不能伪装成多方法高置信判断。
- `to_verify`：现实映射仍有多种可能，优先进入校准候选。
- `excluded`：与用户事实直接冲突，或存在无法消解的同口径冲突。

`structural_confidence=high` 只能用于至少两个不同主要方法家族同向的综合判断。多个证据若共享同一个方法与同一观察，只算一个方法视角。

现实确认状态与结构置信度分开：

- `unverified`：尚未核对；
- `supported`：现实资料部分支持；
- `confirmed`：现实事实明确支持；
- `contradicted`：现实事实直接冲突。

命理方法一致只能提高结构置信度，不能把现实候选变成已经发生的事实。

## 进入报告候选池

每条报告判断必须引用至少一个 `synthesis_id` 和对应的方法现实候选：

- `primary` 判断必须来自至少两个主要方法家族；
- `supplemental` 判断可以来自一个主要方法，但必须登记成立条件、新增信息和反证；
- 用户校准只能调整现实确认状态，不能修改各方法技术结论、现实候选和综合关系。

每个报告领域优先使用多方法主判断，也允许真正新增信息的单方法补充侧面。没有双方法同向时不得硬凑主判断；应使用补充判断或记录证据缺口。不得为了追求多方法一致，删除不矛盾且有区分度的单方法候选。
